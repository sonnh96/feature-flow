# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Overview

- This repository contains a single frontend application located in the frontend/ directory. The app is a TanStack React Start (TanStack Router + React Start) project built with Vite, Tailwind, and Supabase integration. Server entry for Cloudflare Workers is configured to use @tanstack/react-start/server-entry (see frontend/wrangler.jsonc:6).

Common commands

- Install dependencies
  - npm: cd frontend && npm install
  - bun: cd frontend && bun install (a bun.lockb is present)

- Run dev server (local Vite dev server)
  - cd frontend && npm run dev

- Build production bundle
  - cd frontend && npm run build
  - development build mode: npm run build:dev

- Preview production build
  - cd frontend && npm run preview

- Lint and format
  - cd frontend && npm run lint
  - cd frontend && npm run format

- Cloudflare / Worker (optional)
  - The worker entry is set to @tanstack/react-start/server-entry in frontend/wrangler.jsonc:6.
  - To iterate with Wrangler (if you use Cloudflare Workers): cd frontend && wrangler dev (requires wrangler installed/configured).
  - Publishing to Cloudflare would use wrangler publish from the frontend directory; do not publish without checking account/credentials.

- Tests
  - There is no test runner or test scripts configured in package.json. To add tests, we recommend Vitest for a Vite project.
  - Example after adding Vitest: cd frontend && npx vitest run path/to/file.test.ts (runs the specified test file) or npx vitest --watch for interactive testing.

High-level architecture and important files

- frontend/ (app root)
  - frontend/package.json:6-13 — scripts for dev/build/preview/lint/format; use these for local workflows.
  - frontend/wrangler.jsonc:6 — Cloudflare worker/server-entry configuration for SSR with @tanstack/react-start.
  - frontend/.env — contains SUPABASE and VITE_SUPABASE_* variables used by the app. Environment variables are injected via Vite; VITE_ prefixed vars become client-visible. (Do not leak secrets in commits.)

- Routing and server
  - Routing is built with TanStack Router and the route tree is code-generated. The generated file is frontend/src/routeTree.gen.ts (auto-generated by TanStack Router; do not edit) — note the generator comment at the top of that file (routeTree.gen.ts:7-9).
  - The router factory is in frontend/src/router.tsx:getRouter (router.tsx:57) — this is the runtime entry point for creating the client-side router and wiring default error handling.
  - Route files live in frontend/src/routes/*. Files follow TanStack Router file conventions (examples: routes/__root, routes/index, routes/projects.$projectId, etc.). When changing routes, regenerate or let the build regenerate routeTree.gen.ts.

- Supabase
  - Supabase config and SQL migrations live in frontend/supabase/. The app expects SUPABASE_URL and publishable keys available at runtime (frontend/.env). Production DB/keys should be managed via secure secrets (Cloudflare secrets, environment variables in deployment), not committed.

- Styling and tooling
  - Tailwind + Tailwind Vite plugin are used (tailwindcss dependency and @tailwindcss/vite plugin). Styles entrypoint is frontend/src/styles.css.
  - Vite config is at frontend/vite.config.ts.

Developer notes for Claude Code

- Prefer editing files under frontend/src; the routeTree.gen.ts file is generated — do not manually edit it. Reference router.tsx:57 when you need to understand router setup.
- Use the scripts in frontend/package.json for recurring tasks. If you need to add tests, add a test runner (Vitest recommended) and update package.json scripts (e.g., "test": "vitest").
- When working on SSR or Cloudflare-specific behavior, check frontend/wrangler.jsonc and the server entry configuration before making deployment changes.
- When referencing code in responses, include file_path:line_number (this file uses that style in multiple places).

Where to look first when you open the repo

1. frontend/package.json — scripts and dependencies (quick way to see how the project runs).
2. frontend/src/router.tsx:57 — router factory and default error component.
3. frontend/src/routeTree.gen.ts — generated route tree and mapping to src/routes/* files.
4. frontend/src/routes — where route implementations and page components live.
5. frontend/wrangler.jsonc and frontend/.env — deployment/SSR and runtime env variables.
